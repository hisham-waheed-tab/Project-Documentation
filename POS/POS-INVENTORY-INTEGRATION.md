# ربط نقطة البيع بالمخزون

يشرح هذا الملف من أين تأتي الأصناف والأسعار والأرصدة في نقطة البيع، وكيف تُرحَّل المبيعات إلى المخزون.

## 1. القرارات

| الموضوع | القرار |
|---|---|
| قائمة الأسعار | قائمة الجهاز (`PosTerminal.PriceListId`)، وإن لم تُحدد تُستخدم القائمة الافتراضية للفرع (`InvBranchPriceLists`) |
| صنف بدون سعر | يُمنع بيعه |
| الترحيل للمخزون | مجمّع عند إقفال الوردية إلى `TrxInvH` / `TrxInvF` |
| الرصيد | يظهر للكاشير. البيع بالسالب حسب السياسة `STOCK_INSUFFICIENT_MODE` (`Warn` تحذير، `Block` منع) |

## 2. قوائم الأسعار والعملة (Inventory)

- `InvPriceLists.CurrencyCode`: عملة القائمة. كل أسعار القائمة بنفس العملة، ولا يمكن تغييرها بعد إضافة أسعار.
- `InvItemPrices.CurrencyCode`: نسخة من عملة القائمة، تُكتب تلقائيًا عند حفظ السعر.
- `InvBranchPriceLists (TenantId, BranchId, PriceListId)`: القائمة الافتراضية لكل فرع (فرع واحد ← قائمة واحدة). ربط الفرع بقائمة جديدة ينقله من القائمة القديمة.
- الشاشة: مركز الأصناف ← زر «قوائم الأسعار» (درج جانبي). قائمة الجهاز تُحدد من شاشة أجهزة نقطة البيع.

## 3. كتالوج البيع — `GET api/v1/InvPosCatalog/Get?branchId=&storeId=&priceListId=`

يرجع دفعة واحدة:

| الجزء | المحتوى |
|---|---|
| `items` | الأصناف النشطة التي لها وحدة رئيسية |
| `variants` | الـ SKUs (`InvItemVariants`) |
| `units` | الوحدة الرئيسية + الوحدات الأخرى المسموح بيعها (`AllowSale`)، مع `BaseQtyPerUnit` = كمية الوحدة الرئيسية في وحدة واحدة |
| `barcodes` | الباركود لكل (SKU، وحدة) |
| `prices` | أسعار القائمة السارية اليوم. `VariantId = null` = سعر عام لكل SKUs الصنف |
| `stock` | رصيد المخزن بالوحدة الرئيسية لكل SKU (الحركات غير المسودة فقط) |
| `priceListSource` | `terminal` أو `branch` أو فارغ (لا توجد قائمة ← لا يمكن بيع أي صنف) |

`InvPosCatalog` مستثنى من فلتر الصلاحيات (أي مستخدم مسجل يستطيع القراءة).

### في جهاز الكاشير (Desktop)

- كل منتج في الكاشير = SKU × وحدة بيع. السعر: سعر الـ SKU، وإلا السعر العام للصنف، وإلا «بدون سعر» (ممنوع البيع).
- الرصيد المعروض = رصيد الـ SKU ÷ `BaseQtyPerUnit`. فحص الرصيد يجمع كل وحدات نفس الـ SKU في السلة بالوحدة الرئيسية.
- المسح بالترتيب: باركود ← كود الـ SKU (بوحدة البيع الافتراضية) ← كود الصنف (إن كان له SKU واحد). إن وُجد أكثر من احتمال تُعرض للاختيار.
- `PosItemSetting` ما زال يتحكم في الإظهار (`ShowOnPos`) ونوع التسليم.
- سطر البيع يُرسل `ItemId` و`VariantId` و`UnitId`. الصنف المفتوح يُرسل `IsOpenItem = true` ولا يُرحَّل للمخزون.

## 4. الترحيل عند إقفال الوردية

1. `PosShift/Close` ← `PosInventoryPoster.PostShiftAsync` (أي فشل لا يمنع الإقفال، ويُسجل على الدفعة).
2. تُجمع مبيعات ومرتجعات الوردية المكتملة غير المرحّلة (عدا التدريب والأصناف المفتوحة والأسطر بدون وحدة) في دفعة لكل مخزن (`PosInventoryPostingBatch`)، والأسطر مجمّعة حسب (صنف، SKU، وحدة).
3. تُرسل الدفعة إلى `POST {InventoryApi:BaseUrl}/api/v1/InvPosPosting/Post` بتوكن الكاشير.
4. Inventory ينشئ حركة صرف مبيعات وحركة مرتجع بالوحدة الرئيسية، بنوعي الحركة المعلَّمين في `TrxtypeConfig.SystemUsage` (انظر الإعداد). `MyKey = BatchId` يمنع التكرار عند إعادة الإرسال.
5. إعادة المحاولة: `POST PosInventoryPostingBatch/Retry?id=` أو `POST PosInventoryPostingBatch/PostShift?shiftId=`.

## 5. الإعداد المطلوب

- `appsettings.json` في POS: `"InventoryApi": { "BaseUrl": "..." }`.
- نوعا الحركة: العمود `TrxtypeConfig.SystemUsage` يحدد نوع الحركة الذي يستخدمه النظام تلقائيًا:

  | `SystemUsage` | الاستخدام | الشرط |
  |---|---|---|
  | فارغ | نوع عادي | — |
  | 1 | مبيعات نقطة البيع | `TrxKind=1`, `OperatingType=1`, `InOut=2` |
  | 2 | مرتجع مبيعات نقطة البيع | `TrxKind=1`, `OperatingType=1`, `InOut=1` |

  - نوع واحد فقط لكل استخدام لكل فرع، ونوع واحد بدون فرع (index فريد + تحقق عند الحفظ).
  - الترحيل يأخذ نوع الفرع، وإلا النوع الذي بدون فرع، وإلا تفشل الدفعة برسالة واضحة.
  - يُضبط من شاشة أنواع الحركات (حقل «استخدام النظام»)، واختيار الاستخدام يضبط نوع الحركة والتشغيل والاتجاه تلقائيًا.
  - السكريبت [../Inventory/sql/pos-trxtype-system-usage.sql](../Inventory/sql/pos-trxtype-system-usage.sql) ينشئ النوعين بدون فرع (كود 50 و51) لكل tenant ليس لديه.
- قائمة أسعار افتراضية لكل فرع، وعملة لكل قائمة.
- مخزن افتراضي لكل جهاز (`PosTerminal.DefaultStoreId`)؛ الدفعة بدون مخزن تفشل.
- الصلاحيات: [../Inventory/sql/pos-inventory-posting-permissions.sql](../Inventory/sql/pos-inventory-posting-permissions.sql) يعطي `InvPosPosting.Create` لكل من يملك `PosShift.Update`، ويضيف `InvPosPosting` إلى قائمة `PosCashier`.

## 7. حدود معروفة

- لا توجد شاشة في Front لدفعات الترحيل وإعادة المحاولة؛ المتاح API فقط (`PosInventoryPostingBatch`).

- الرصيد في الكتالوج لا يشمل مبيعات الوردية الحالية غير المرحّلة (الجهاز يخصم ما في السلة فقط).
- رقم الحركة = أكبر رقم + 1، فإرسال دفعتين في نفس اللحظة قد يتعارض.
- أسطر البيع القديمة بدون `UnitId` لا تُرحَّل.
- التسليم المؤجل يُرحَّل عند إقفال الوردية مثل الفوري.
- رصيد الأصناف ذات المتغيرات المسجل بدون SKU يُحسب على الـ SKU الافتراضي، فلا يظهر على SKUs البيع.
